# PingoraHub 第一阶段开发任务拆分

## 1. 阶段目标

第一阶段的目标不是把平台所有能力一次做完，而是尽快打通下面这条主链路：

`控制台创建站点 -> 绑定节点 -> 生成配置版本 -> 节点感知变更 -> 拉取配置 -> 热更新 -> ACK 回传`

同时补上两条关键配套链路：

- `DNS Provider 接入 -> DNS 记录管理 -> ACME DNS-01 证书申请`
- `节点状态监控 -> 主节点故障识别 -> 备用节点接管 -> 模板化运维动作执行`

## 2. 里程碑

### 里程碑 M1：项目骨架与基础设施

交付：

- Rust workspace 骨架
- PostgreSQL 初始化迁移
- 基础配置加载
- 最小 `hub-api` 健康检查接口
- 日志和错误处理基础能力

验收标准：

- `cargo check` 通过
- 数据库可执行初始化迁移
- API 服务可正常启动

### 里程碑 M2：节点生命周期闭环

交付：

- 节点创建
- 首次注册
- 节点 access token / refresh token
- 心跳接收与在线状态判定
- 节点列表与状态查询

验收标准：

- 节点可完成首次注册
- 控制台可看到在线/离线状态
- 节点心跳异常时可正确切换到 `suspect/offline`

### 里程碑 M3：站点与发布闭环

交付：

- 站点创建和编辑
- 主备节点绑定
- 站点配置版本化
- 发布记录生成
- 节点最新版本查询
- 节点配置包拉取
- 节点 ACK 回传

验收标准：

- 单站点变更可成功下发到目标节点
- 节点应用成功后能正确更新状态
- 发布失败可定位到具体节点

### 里程碑 M4：DNS 与证书闭环

交付：

- DNS Provider 接入
- Zone 同步
- DNS 记录新增/修改
- ACME `DNS-01` 自动签证任务
- 证书与站点绑定

验收标准：

- 可使用一个真实 DNS Provider 完成 Zone 同步
- 可触发一次测试域名证书申请
- 证书下发后可生成新的站点配置版本

### 里程碑 M5：监控与主备切换

交付：

- 节点故障检测
- 主备切换策略
- 备用节点配置接管
- 模板化运维动作执行
- 运维动作结果回传

验收标准：

- 模拟主节点离线后，可将站点发布到备用节点
- 可执行一条模板化 VIP 绑定动作
- 全流程有审计与执行结果记录

## 3. 工作分解结构

## 3.1 数据与基础设施

任务：

- 建立 PostgreSQL 初始表结构和索引
- 设计 etcd key 命名规范
- 设计 Redis key 命名规范
- 落地环境配置模型和密钥加载方式

产出物：

- `migrations/0001_init.sql`
- `docs/infra-key-design.md`，后续可补
- Rust 配置模块

## 3.2 管理端 API

任务：

- 节点管理接口
- 站点管理接口
- 绑定关系接口
- DNS Provider / Zone / Record 接口
- 发布接口
- 故障切换策略接口
- 运维动作模板接口

验收重点：

- 请求参数校验完善
- 资源变更写入审计日志
- 高风险接口支持幂等和审批字段

## 3.3 节点 Agent 协议

任务：

- 注册协议
- 心跳协议
- 配置拉取协议
- 发布 ACK 协议
- 运维动作结果回传协议

验收重点：

- 节点重试具备幂等性
- 节点掉线重连可重新对账最新版本

## 3.4 配置编排与发布

任务：

- 把站点配置编译成节点配置包
- 生成版本号、摘要和签名
- 将发布元信息写入 PostgreSQL
- 将版本指针写入 etcd
- 保存节点维度发布状态

验收重点：

- 同一版本可重复下载
- 发布失败不影响已生效的旧版本
- 节点可回滚到前一稳定版本

## 3.5 DNS 与证书

任务：

- 设计 DNS Provider 适配接口
- 实现至少一个 Provider，例如 Cloudflare
- 实现 ACME `DNS-01` 验证任务流
- 证书入库、绑定、版本化下发

验收重点：

- DNS 凭据加密存储
- DNS 变更有审计
- 证书申请失败可追踪错误原因

## 3.6 监控、故障切换与运维动作

任务：

- 节点离线判定策略
- 切换策略引擎
- 备用节点预热发布
- 运维动作模板渲染和参数校验
- 节点执行结果回传

验收重点：

- 避免同一故障重复切换
- 不开放任意 shell
- 重点命令支持审批

## 4. 推荐开发顺序

1. 先完成数据库迁移、配置加载、基础 API 进程
2. 再完成节点注册、认证、心跳和状态查询
3. 然后完成站点配置、绑定关系和发布闭环
4. 接着补 DNS Provider、证书申请与绑定
5. 最后完成监控聚合、故障切换和运维动作

## 5. 任务清单

### P0

- 建立 Rust workspace 和迁移体系
- 实现节点创建、注册、心跳
- 实现站点创建、绑定、发布
- 实现节点拉取配置和 ACK

### P1

- 实现 DNS Provider 接入
- 实现 ACME 证书申请
- 实现节点状态聚合
- 实现主备切换策略
- 实现模板化 VIP 绑定动作

### P2

- 补 OpenAPI 文档
- 补集成测试和失败注入测试
- 接入 Prometheus / Loki / Alertmanager

## 6. 角色建议

- 后端 Rust：负责 API、发布编排、任务编排
- 平台工程：负责 PostgreSQL、Redis、etcd、部署与安全
- 运维 / 网络：负责 VIP 接管动作模板和故障切换预案
- 前端：负责控制台页面和审计展示

## 7. 风险控制建议

- 先用“模板化命令”替代“任意 shell”
- 默认主节点恢复后不自动回切
- 证书私钥与 DNS Token 一开始就按高敏感等级处理
- 第一阶段优先打通单租户、单区域、单 DNS Provider 场景
